# Why OOP? — a Unity walkthrough

A tiny RuneScape-style arena: a knight, some skeletons, a sword. Each scene adds one idea from
object-oriented programming, and each idea is introduced by first showing the problem it solves.

You don't need to have written a Unity game before. You do need to be willing to open the scripts
and read them. They're short on purpose.

## Opening the project

1. Open this folder in **Unity 6** (6000.x) via Unity Hub.
2. Wait for the import to finish the first time. The KayKit models take a minute.
3. From the menu bar, pick **OOP Demo** and build the scene you want:

| Menu item | Scene it creates | Idea |
|---|---|---|
| Build Scene 1 - Cold Open | `Scenes/Scene1_ColdOpen` | The problem: loose variables |
| Build Scene 2 - Classes and Objects | `Scenes/Scene2_ClassesAndObjects` | Classes, objects, instances |
| Build Scene 3 - Encapsulation | `Scenes/Scene3_Encapsulation` | `private`, and why it matters |

Building a scene is safe to repeat. It regenerates the scene file from scratch, so if you break
something while experimenting, just build it again.

## Controls (all scenes)

- **Left-click the ground** to walk there.
- **Left-click a skeleton** to walk up and attack it. The hero keeps swinging until it's dead.
- Scene 3 adds **K** (kill all) and **H** (heal all).

## Where things are

```
Assets/
  Scripts/
    00_Shared/              HealthBar, FollowCamera. Plumbing. Not the point.
    01_ColdOpen/            Scene 1 scripts + README
    02_ClassesAndObjects/   Scene 2 scripts + README
    03_Encapsulation/       Scene 3 scripts + README   (Solution/ has the fixed versions)
  Editor/OOPDemo/           The script behind the OOP Demo menu. You can ignore it.
  KayKit/                   3D models and animations (CC0, by Kay Lousberg)
  Prefabs/                  Generated by the menu
  Scenes/                   Generated by the menu
```

Each `Scripts/0X_.../README.md` tells you what to look at in that scene and what to try.
Start with `01_ColdOpen`.

## A note on the scripts

Every scene's scripts sit in their own C# namespace (`Lecture01`, `Lecture02`, ...). That's only so
that three different versions of a class called `Enemy` can live in one project without colliding.
Inside a scene you never have to think about it.
